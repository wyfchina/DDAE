# DDAE 统一场景结果视图设计

## 背景与问题

冻结基线多方案比较已经由 `/api/scenario-runs/compare` 返回完整结果，但前端存在两条互不连通的数据链：

- 新比较链使用 `state.futureComparison`，目前只驱动方案卡片、能力保护顶部表和击穿顶部表。
- 旧预览链使用 `state.preview`、`state.bufferTrend`、`state.rccp` 和 `state.supplierCollaboration`，继续驱动库存、通用 RCCP、供应与异常工作台。

“候选组合 KPI 对比”和“候选动作影响矩阵”还读取已经不存在于新比较 DTO 中的字段，因此比较完成后仍显示占位文字。

## 方案选择

### 方案 A：只修复两张空表

把新比较结果转换成两张表所需的行，但不处理各二级页面。改动小，但用户仍无法查看方案的库存、能力和供应明细，不能形成评审闭环。

### 方案 B：统一方案选择器与结果上下文（采用）

以 `state.futureComparison` 为唯一的新比较结果源，维护一个选中 `responseId`。方案比较、库存缓冲、能力缓冲、供应风险和击穿分析共用该选择；每次切换都从同一个 `ScenarioComparisonCase.preview.scenario` 渲染完整工作区。

优点是语义一致、复用后端结果、无需复制计算公式，也能消除旧空表。用户已批准采用此方案。

### 方案 C：每个二级页面维护独立选择

每页都可选择不同方案，局部灵活，但容易出现库存看方案一、能力看方案二的上下文错位，不适合会议评审。

## 设计

### 统一状态

- 新增 `state.futureComparisonSelection.responseId`，表示当前查看方案。
- 比较完成后，优先选择可评审方案；没有可评审方案时选择“不采取措施”。
- 提供辅助函数读取全部方案、当前方案及当前方案的 `preview.scenario`。
- 旧的单方案“运行预览”继续使用 `state.preview`，保持向后兼容；只有完成冻结比较后，统一方案上下文才接管五个结果视图。

### 统一选择器

- 在“方案比较”结果区提供主选择器，显示“不采取措施”和每个企业响应方案，并附可行性标签。
- 在库存、能力、供应和击穿页面显示同一选择器值；任一页面切换时，其余页面同步更新。
- 选择器只改变查看上下文，不保存、不选定、不审批、不生效。

### 方案比较

- “候选组合 KPI 对比”改为基于 `allCases` 计算相对于“不采取措施”的指标变化。
- “候选动作影响矩阵”每行对应一个响应方案，展示作用对象、服务、库存、负荷、供应、订单、约束和可行性。
- 不再读取 `combinationComparisons` 或 `candidateImpactMatrix` 旧字段。

### 库存缓冲

- 使用当前方案的 `preview.scenario.bufferTrend`、`inventoryFlow` 和证据集合。
- 方案切换后保留仍然存在的 SKU；不存在时回退到该方案第一个 SKU。
- 红黄绿区域、净流量位置、在手库存、需求波动和订单明细均来自同一个当前方案。

### 能力缓冲

- 顶部保护消耗、CCR 利用率和四色分布按当前方案显示，不再把所有方案混排。
- 下方通用 RCCP、约束与资源明细使用当前方案的 `rccp` 和 `constraints`。
- 页面明确显示当前方案名称。

### 供应风险

- 使用当前方案的 `supplierCollaboration` 和 `supplierCapacity`。
- 尽量保留当前供应商选择；若不存在则回退到该方案默认供应商。

### 击穿分析

- 顶部击穿与时间保护证据按当前方案过滤。
- 下方异常工作台仍属于基线异常来源，不伪装成方案结果；增加说明区分“方案击穿结果”和“基线异常信号”。

### 保存与重新载入

- 本次整改保证比较完成后的统一查看。
- 保存仍沿用现有冻结比较保存端点和人工选定流程。
- 已保存方案详情本身包含完整 `ScenarioRunPreviewResult`；用户显式点击已保存运行时复用同一视图渲染入口，不新增外部接口。启动、刷新列表或保存后的自动详情加载不得覆盖当前实时比较上下文。

## 错误处理与边界

- 没有比较结果时，各页面保留现有基准工作台并提示先运行冻结比较。
- 当前方案缺少某类证据时显示“证据缺失”，不得回填其他方案或按零处理。
- 不修改 `DDAE_INTERFACE_CONTRACT`、SDBR DTO、ACK、错误码、JSON 形状、端点或契约测试。
- 不修改 `DDAE-NetworkStructure`，不生成完整执行排程，也不自动保存、选定、审批或生效。

## 验收测试

- 新比较完成后，两张旧空表显示全部方案与响应动作。
- 选择任一方案后，方案比较、库存、能力、供应和击穿页面显示相同方案名称。
- 库存工作区使用选中方案的缓冲趋势与库存流。
- 能力顶部和完整 RCCP 使用同一选中方案，且不再混排所有方案。
- 供应工作区使用选中方案的供应数据。
- 击穿表只显示选中方案；基线异常区有明确来源说明。
- 无比较结果时旧预览和基准页面仍可用。
- 现有白盒追踪、公开演示闭环、SDBR/Network/CONTRACT 行为保持不变。
