# DDAE 五阶段工作台修订设计

日期：2026-07-15
状态：已完成口头设计确认，待书面规格复核
目标分支：`codex/ddsop-five-stage-workbench`
设计基线：`ba78171`

## 1. 目标

在不改变任何外部协议的前提下，修订 DDAE 五阶段工作台，使它能够清楚表达 DDS&OP 从历史事实、当前基线、未来场景、DDOM 配置决策到行动闭环的业务关系，并纠正现有演示数据、保护对象、时间缓冲和导航交互中的问题。

本次修订重点包括：

- 把五个业务阶段改成真正的页面切换，不再依靠长页面滚动定位。
- 为五个一级入口增加层次明确、标题不超过六个字的二级入口。
- 修正历史数据口径，使六个月和十二个月结果不同且量级合理。
- 将当前时点指标放入“当前状态基线”，历史页只展示选定期间的历史结果。
- 正确区分库存缓冲、时间缓冲、能力缓冲和供应风险。
- 将 FPGA 设置为独立库存控制点，不再作为时间或能力保护。
- 明确 03、04、05 三个阶段之间的来源、证据和反馈关系。
- 保留白盒追踪和公开演示闭环两个独立验证页面。

## 2. 不可突破的边界

### 2.1 外部协议

本次新增或修改的业务代码不得新增、修改、重新解析、调用或依赖任何外部协议，包括但不限于：

- DDAE 与 SDBR/DDOM 之间的接口协议；
- 网络结构评分协议及评分结果格式；
- `DDAE_INTERFACE_CONTRACT` 中的字段、状态、ACK、错误码、JSON 形状、样例、端点和契约测试；
- 任何 CSV、JSON 或文件导入协议；
- 任何新的外部系统连接器或适配器实现。

既有“公开演示闭环”和网络入口作为不透明的遗留能力原样保留。其协议处理逻辑、端点、payload 和按钮行为均属于禁止变更区域；既有协议调用只由原有页面和原有回归测试继续验证，不得成为五阶段业务页面的输入来源，也不得参与内部自动计算。

### 2.2 仓库

- 不修改 `DDAE_INTERFACE_CONTRACT`。
- 不修改 `DDAE-NetworkStructure`。
- 只修改 DDAE 功能分支工作树。
- 最终差异检查必须证明上述两个外部目录没有变化。

### 2.3 决策权限

DDAE 只做事实回顾、基线冻结、场景模拟、治理建议和行动记录：

- 不生成执行排程；
- 不自动采纳建议；
- 不自动批准变更；
- 不自动使变更生效；
- 不向 SDBR、DDOM 或其他外部系统发布结果；
- 不因网络评分或 SDBR 反馈自动修改主设置。

## 3. 信息架构与命名

### 3.1 一级与二级入口

| 编号 | 一级入口 | 二级入口 | 核心职责 |
|---|---|---|---|
| 01 | 历史回顾 | 经营结果、缓冲表现、能力约束 | 回顾已经发生的经营结果和保护效果 |
| 02 | 当前状态基线 | 会前快照、证据检查、版本冻结、审计记录 | 形成会前可信、可追溯且不可变的事实起点 |
| 03 | 未来场景模拟 | 场景配置、方案比较、库存缓冲、时间缓冲、能力缓冲、供应风险、击穿分析 | 在同一冻结基线上比较外部变化和不同响应方案 |
| 04 | DDOM 配置决策 | 结构设置、参数决策、临时调整、变更记录 | 把认可的场景结果转成待人工治理的配置建议 |
| 05 | 行动和决策 | 问题清单、行动跟踪、决策记录、结果验证 | 管理跨部门问题、行动、决策及实施效果 |

所有二级标题均不超过六个汉字。“能力供应”不再作为一个混合分类：资源能力保护归入“能力缓冲”，外部物料供应不确定性归入“供应风险”。

### 3.2 验证与追踪分组

侧栏在五个主业务阶段之后保留“验证与追踪”分组：

1. `白盒追踪`
2. `公开演示闭环`

两个页面继续是独立一级入口，不并入任何业务阶段；`公开演示闭环`始终位于侧栏最底部。

## 4. 导航与页面切换

### 4.1 交互规则

- 点击五个一级入口时，展开该阶段的二级入口，同时打开该阶段概览。
- 同一时刻只展开一个业务阶段。
- 点击二级入口时，只显示对应子页面，不通过页面滚动寻找内容。
- 切换页面时保留尚未提交的表单状态。
- URL 哈希记录当前一级和二级页面，支持刷新、浏览器前进和后退。
- 侧栏保持固定；内容较长时只允许当前子页面内部正常滚动，不允许滚动穿越到其他业务阶段。
- 面包屑显示“一级入口 / 二级入口”。
- 一级、二级入口通过缩进、连接线、展开符号和选中状态体现层级。

### 4.2 兼容性

- 移除用于滚动联动导航的 `IntersectionObserver`。
- 保留白盒追踪和公开演示闭环现有页面 ID、关键 DOM 标识、按钮和深链接。
- 原有内部 API 不因导航改变而变化。

## 5. 阶段关系

主业务链为：

`01 历史回顾 → 02 当前状态基线 → 03 未来场景模拟 → 04 DDOM 配置决策`

行动闭环不是简单排在 04 之后，而是横跨场景与配置决策：

- 03 可以直接创建 05 的问题或行动事项。
- 03 形成 04 的配置变更建议时，必须保存来源基线和来源场景。
- 04 的一个变更包可以关联多个 05 行动事项。
- 05 的决策和实际效果可以回到 04 作为复查证据，但不得自动推进 04 的状态。
- 05 的实际效果经内部人工确认或演示事实记录后，在下一周期进入 01 的历史事实和 02 的新候选基线；不得自动从外部系统、网络评分或 SDBR/DDOM 获取或回灌。

系统必须提供正向链接和反向查询，使用户能够从场景找到变更与行动，也能从变更或行动返回来源场景。关联缺失时显示“未关联”，不得猜测关系。

## 6. 历史回顾

### 6.1 数据口径

历史回顾只展示选定期间内已经发生的结果，不展示未来预测，也不把当前快照冒充历史平均值。

- 近六个月使用最近 26 个周事实。
- 近十二个月使用最近 52 个周事实。
- 六个月与十二个月分别聚合，不允许返回完全相同的固定结果。
- 详细窗口按所选对象的最大累计提前期确定。
- 当前时点的服务、库存、在制品、供应和能力状态移入 02“会前快照”。

### 6.2 演示数据

新增明确标记为“演示数据”的内部周度历史事实。演示企业按中等规模卫星制造场景校准：

- 整星和载荷数量为个位数到低两位数；
- 关键组件数量为几十到数百；
- 当前总库存金额目标量级约为人民币 6,000 万至 1 亿元；
- 六个月和十二个月应体现不同的需求、交付、库存、在制品和异常事件分布；
- 现金占用不得直接复制库存金额，必须由有证据的库存、在制品或相关资金事实计算；证据不足时显示“证据缺失”。

异常费用只来自显式的加急、外协或返工事件。不得再使用“未来红色供应窗口数量 × 固定金额”的伪历史算法。“红色供应窗口”这一含混用户术语从业务界面移除，供应预测改用“供应高风险周期”。

### 6.3 缓冲与控制点

历史页区分三种状态：

- 已设计保护；
- 保护当前可用；
- 保护实际有效。

证据不足显示“证据缺失”，不适用显示“不适用”，两者都不得显示为零或正常。

库存保护至少包含以下独立控制点：

- 热控结构件库存控制点；
- 星载电子半成品库存控制点；
- 关键进口 FPGA 库存控制点。

`AV-FPGA-203` 只属于 FPGA 库存控制点。删除它作为时间缓冲或能力保护对象的重复表达。

缓冲表现展示区域停留比例、进入红区次数、连续时长、恢复时间和显式异常原因。

### 6.4 能力保护与约束

能力视图必须区分：理论能力、标准能力、经验证能力、计划可用能力、承诺负荷、保护能力、已消耗保护和损失原因。

能力保护的业务语义为：保护 CCR 的流动，主要评估 CCR 前方具有明确工艺顺序证据的资源是否占用了应保留的能力。实现规则如下：

- CCR 本体展示利用率和状态，只作为上下文，不把普通空闲量直接称为保护能力。
- 只有具有工艺顺序证据、被明确认定为保护 CCR 的上游资源才能计算保护能力和保护消耗。
- 没有路径顺序或保护关系证据时显示“证据缺失”。
- 普通资源的空闲能力称为“未承诺能力余量”，不得称为保护。
- TVAC 当前只作为“场景潜在 CCR”，不得显示为已确认的当前 CCR。

约束分为当前 CCR、高负荷资源、场景潜在 CCR、事件型约束和外部约束。

## 7. 当前状态基线

### 7.1 候选基线

通过内部 `ICurrentBaselineDataSource` 获取候选基线。当前仅提供明确标注为“演示数据”的种子适配器，不连接外部系统。

候选基线包含：库存、在途、积压、在制品、供应承诺、资源能力、临时措施、当前主设置版本，以及场景计算需要的工艺顺序、控制点进展、时间缓冲定义等内部计划输入。

“会前快照”展示截至基线截止时间的服务水平、库存金额、在制品、积压、供应覆盖和资源负荷等当前状态。服务水平不是瞬时量，必须同时显示其统计窗口；所有指标必须显示来源和截止时间。

### 7.2 证据检查

每个部分显示：

- 来源；
- 截止时间；
- 新鲜度；
- 完整性；
- 缺失原因。

关键部分缺失、过期或不完整时禁止冻结。证据缺失不得转换成零。每个证据部分是否关键由内部基线定义明确标记，不由页面临时推断。

时间缓冲采用以下唯一规则：未配置时间缓冲时标为“不适用”；已经配置但定义或进展事实缺失时标为“证据缺失”，只禁止相应时间缓冲分析，不阻止其他完整部分冻结；只有当该时间控制点被内部基线定义明确标为本次关键证据时，缺失才阻止整个基线冻结。

### 7.3 版本冻结

- 冻结产生不可编辑的 SQLite 快照。
- 冻结后只能创建新版本，不能覆盖原版本。
- 新版本号单调递增。
- 所有场景比较必须引用一个已冻结版本。
- 同源比较必须引用同一冻结基线。

### 7.4 审计记录

审计至少记录：候选版本、冻结版本、操作者、时间、证据摘要和冻结结果。场景、变更包和行动事项对基线的引用可从详情页反向查看。

## 8. 未来场景模拟

### 8.1 输入来源

本次只允许三类内部输入：

1. **冻结基线**：来自 02，提供不可变的当前事实。
2. **外部场景假设**：由用户在页面人工录入，或选择明确标注为“演示数据”的内置模板。
3. **响应配置**：由用户人工设置的企业应对措施。

新增内部 `IScenarioAssumptionSource` 扩展点，但本次只保留接口和内置演示实现，不提供任何外部适配器。“外部场景”表示企业面对的外生变化，不表示数据来自外部系统。该抽象不得包含具体外部端点、认证、文件格式或网络协议，也不得调用网络评分或 SDBR/DDOM。

本次不增加 CSV/JSON 导入，不增加外部系统连接器，不读取任何外部评分或协议数据。

人工场景假设显示来源类别、录入人、录入时间、生效区间和假设依据；演示模板显示模板名称、版本和“演示数据”标记。只有冻结事实使用“截止时间”，场景假设不把生效区间称为截止时间。

### 8.2 场景与响应分离

外部场景包括需求变化、供应风险、能力损失和已知事件。响应配置包括提前建库、临时能力、MOQ/订货周期覆盖和供应响应等企业措施。

响应配置不得修改外部场景定义。同一冻结基线、同一外部场景下必须支持：

- 不采取措施；
- 一个或多个响应方案；
- 统一展望期和统一比较口径。

### 8.3 三类缓冲与供应风险

#### 库存缓冲

评估库存控制点的区域状态、最早进入红区周期、连续风险时长、恢复周期、影响产品和原因。FPGA 在此作为独立库存控制点。

#### 时间缓冲

时间缓冲单独分析，不能包含在能力缓冲或供应风险中。它面向明确的控制点和工艺位置，评估在场景延误下，流动相对于缓冲时长的侵入。

输入来自冻结基线中的内部时间缓冲定义、控制点到达或就绪事实，以及人工场景中的延误假设。演示环境使用内部种子事实。没有时间位置或进展证据时显示“证据缺失”，不得推断。

输出包括：

- 受保护控制点；
- 缓冲时长；
- 最早风险周期；
- 最大侵入比例；
- 连续风险时长；
- 恢复周期或“展望期内未恢复”；
- 影响产品族和主要原因。

DDAE 只做战术风险模拟，不生成订单顺序、资源执行排程或下达指令。

#### 能力缓冲

评估有明确保护关系的上游资源对 CCR 的保护余量、保护消耗和恢复。CCR 本体利用率可展示，但不能取代保护资源的计算。

#### 供应风险

供应风险不是第四种 DDOM 缓冲。它是外部条件和击穿原因，单独展示供应覆盖缺口、最早高风险周期、持续时间、恢复状态和受影响库存控制点。

### 8.4 击穿分析

后端对白盒输入重新计算库存、时间、能力和供应风险。跨对象汇总最早击穿周期、位置、连续风险时长、恢复周期、影响产品和主要原因。展望期内未恢复时必须明确标识。

前端只提交场景参数和显示后端结果，不复制 DDMRP、RCCP、供应或时间缓冲公式。

## 9. DDOM 配置决策

配置建议分为：

- 结构设置；
- 主参数决策；
- 临时调整。

变更包记录创建方式、来源基线、来源场景、当前值、建议值、负责人、审批人、生效日期、失效日期、复查日期、预期效果和回滚条件。

所有新变更包都必须引用来源基线。由 03 派生的变更包还必须引用来源场景，创建方式为“场景派生”；允许人工独立创建变更包，此时来源场景为空，创建方式为“人工创建”。既有缺少来源的历史记录不回填猜测值，只显示“未关联”。

状态只允许人工推进，并保留审计链。不得增加自动采纳、自动审批或自动生效。

网络结构入口作为不透明遗留入口按现状保留；本次不修改其代码，不增加调用能力，不读取网络评分、不解释评分协议，也不把评分结果转成建议。

现有 SDBR 反馈只保留在独立验证页面。本次五阶段业务区不读取、不显示、不解释该反馈。

## 10. 行动和决策

事项包含：问题、影响对象、所属场景、服务/库存/现金/风险影响、决策要求、负责人、截止日期、升级层级和下次验证点。

状态流为：

- `待处理 → 进行中 → 已完成`
- `待处理/进行中 → 已升级`
- `已升级 → 进行中`

用户界面不显示 `Open`、`InProgress`、`Escalated`、`Completed` 等普通英文状态，但内部存储值可以保持兼容。

事项对场景运行和主设置变更包的关联均为可选。一个场景可以关联多个变更包和多个行动事项；一个变更包可以关联多个行动事项；一个行动事项最多引用一个场景和一个变更包。所有创建、状态、人工决策和结果更新写入 SQLite 追加式审计链。

## 11. 白盒与协议验证页面保护

### 11.1 白盒追踪

- 保留独立侧栏入口、DOM 标识、中文标签、计算阶段和 trace 展示。
- 保持后端重算以及输入—计算—输出证据链。
- 不接受前端结果作为权威计算。
- 场景页面可以链接到白盒记录，但完整 trace 仍在独立页面查看。

### 11.2 公开演示闭环

- 保留独立入口并位于验证分组最底部。
- 保留刷新、payload 写出、适配器审计、ProductDemo 档案、DDAE→SDBR payload 和 SDBR→DDAE 反馈解释。
- 保留现有页面 ID、按钮行为、API 请求、证据标签和底部业务用户视图。
- 不修改 `/api/public-demo-golden-loop`、`/write-payload`、AdventureWorks 档案端点或 integration-contract 端点。
- 不修改契约实现类、fixtures、contract repository 文件或协议回归断言。
- 此页面为了验证既有协议，可以保留协议规定的英文标识；其他业务页面应尽量中文化。

## 12. 数据质量与界面语言

### 12.1 损坏演示记录

当前 SQLite 中已识别的 Codex 烟测乱码记录应按精确 ID 清理，不得重置整个数据库或删除用户记录：

- `09944ca75dfa4efab765d1481c860709`
- `8aead2083210423db98e9f35924c7f8e`

## 13. 内部架构与数据持久化

### 13.1 内部服务边界

- 历史事实源负责提供周度实际事实；历史服务负责 26/52 周聚合。
- 当前基线源负责候选事实；基线服务负责证据检查、冻结和审计。
- 场景假设源只负责内置演示模板；人工输入由内部场景请求处理。
- 场景比较服务负责同源方案比较。
- 保护击穿分析器分别计算库存、时间和能力缓冲；供应风险分析器单独计算供应覆盖缺口及其影响。
- 配置治理服务负责人工变更包。
- 行动协调服务负责事项、状态、决策、关联和审计。

每个服务只依赖内部领域模型，不引用外部合同 DTO。

### 13.2 SQLite

只做增量建表或增量加列，不删除和重建现有业务数据。冻结基线保持不可变；历史事实、基线审计、事项审计和关联记录均保留来源与时间。

### 13.3 内部 API

保留和完善以下 DDAE 内部 API：

- `GET /api/history-review`
- 当前基线候选、创建、列表和详情端点
- `POST /api/scenario-runs/compare`
- 协调事项创建、列表、详情、状态、决策和审计端点

`/api/scenario-runs/preview` 保持向后兼容。时间缓冲结果作为内部比较响应的一部分，不创建外部协议。内部 DTO 只能增加可选字段，不引用或修改 SDBR/CONTRACT DTO。

## 14. 错误处理

- 基线不完整：返回明确缺失部分，禁止冻结。
- 基线未冻结：禁止场景比较。
- 场景证据不足：保留场景但将相应结果标为“证据缺失”，不得补零。
- 时间缓冲无工艺位置或进展事实：不计算侵入，显示缺失原因。
- 能力保护无上游顺序证据：不计算保护消耗，显示缺失原因。
- 方案比较来源不一致：拒绝比较并指出不同的基线或外部场景。
- 本次不存在外部适配器：界面和新增后端代码不得显示外部导入入口或尝试网络连接；收到非内部来源标识时拒绝处理并记录原因。
