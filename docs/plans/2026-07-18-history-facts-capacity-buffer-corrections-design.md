# 历史事实、缓冲表现与产能保护修正设计

日期：2026-07-18

状态：已确认，待实施计划

范围：仅 DDAE 内部历史事实、当前基线、历史回顾界面与演示数据

## 1. 背景

现有“历史回顾”已经具备经营结果、缓冲表现、能力约束等页面，但复核发现以下问题：

1. “剩余保护”容易被误解为 CCR 自身的备用产能，且期间平均值会掩盖个别保护耗尽周。
2. 演示在手库存不是按库存收发连续滚算；开放供应又接近合格需求，导致在手库存与净流量位置长期机械重合。
3. “目标净流量位置”是程序自定义的缓冲区中点，不是必要的 DDMRP 历史事实。
4. 参数快照、每周原因和证据完整性在页面中混为一体，证据内容没有充分展开。
5. 所有 SKU 共用同一需求波动模板，切换 SKU 后只有数值缩放，曲线形状没有实质变化。
6. FPGA 的 MOQ=80 造成绿色区域被 MOQ 异常放大；业务确认统一主数据应为 MOQ=5。
7. 当前“期间能力”是多阈值时间序列，不是产能缓冲分布；“期间上游负荷分布”与其数据重复。
8. 历史经营结果与当前状态基线来自两套独立演示事实，缺少截止点衔接和余额对账。

## 2. 边界与不变量

本次只修改 DDAE 内部实现。

必须保持以下边界：

- 不修改 `DDAE_INTERFACE_CONTRACT`。
- 不修改任何 SDBR 字段、状态、ACK、错误码、端点、样例或契约测试。
- 不修改 `DDAE-NetworkStructure`，也不读取或写入网络评分协议。
- 不新增外部导入协议，仅保留现有内部数据源适配器边界。
- 不生成完整执行排程，不自动批准、自动生效或自动发布任何结果。
- 保留“白盒追踪”和“公开演示闭环”独立页面、入口、DOM 标识和原有行为。
- 不引入新的前端图表依赖，继续使用现有 HTML、CSS 和 SVG 绘制能力。

## 3. 方案选择

评估过三个方案：

### 方案 A：只修改标签和图形

修改术语、删除“目标净流量位置”、替换能力图，但保留原有演示事实生成方式。

优点是改动小；缺点是在手库存、净流量位置、SKU 波动和历史—基线关系仍然不可信，因此不采用。

### 方案 B：建立一致的内部演示事实链

在现有 seed/adapter 架构内建立一套连续、可复算的内部演示事实，让历史经营结果、缓冲表现和当前基线共享相同事实集及截止口径，同时修正页面表达。

该方案不引入外部协议，能够解决当前业务解释和演示可信度问题，采用此方案。

### 方案 C：建立完整交易级库存与产能事件账

新增正式收货、领用、报废、工序完工和能力事件模型，由交易事件动态生成全部历史与基线。

该方案长期最完整，但当前范围过大，并接近完整执行数据平台，不纳入本次实施。

## 4. 统一内部事实链

### 4.1 共享事实集

历史回顾和当前基线必须引用同一个内部演示事实集，事实集至少具有：

- `FactSetId`
- `SourceKind=DemoFixture`
- `HistoryThroughUtc`
- `BaselineAsOfUtc`
- 统一的 SKU、资源和单位成本范围
- 可复算的库存、需求、供应、能力和经营结果事实

历史经营汇总使用截止日前 26 或 52 个已关闭周；当前基线冻结同一事实链在会前截止时刻的状态。

### 4.2 范围一致性

- 企业级历史经营库存金额与当前基线库存金额使用同一组 12 个 SKU。
- “缓冲表现”仍只展示配置了 DDMRP 缓冲的 SKU，不因企业级汇总范围扩大而虚构其他缓冲。
- 资源主数据、单位成本和控制点归属必须由相同 seed 主数据提供。

### 4.3 截止点衔接

当前基线必须保存：

- 来源历史事实集编号
- 最近已关闭历史期间截止时间
- 当前基线截止时间
- 截止间隔内增加、减少和调整
- 对账状态及差异原因

存量指标遵循：

```text
当前基线余额
= 最近历史期末余额
+ 截止间隔内增加
- 截止间隔内减少
± 经标识的调整
```

服务水平、流动时间和异常费用属于期间指标，不与时点余额强行相等，但必须显示统计窗口并引用同一事实集。

## 5. 库存缓冲事实

### 5.1 在手库存连续滚算

每个 SKU 每周遵循：

```text
期末在手库存
= 期初在手库存
+ 本周实际收货
- 本周实际消耗
± 库存调整
```

下一周期的期初在手库存等于上一周期的期末在手库存。不得再根据企业库存金额目标反推每周数量。

演示数据应体现合理的消耗、补货和恢复节奏。受保护物料的在手库存应主要经历黄区和红区，并允许在到货后短期恢复至绿区；这是一项演示分布要求，不作为所有真实物料必须满足的理论约束。

### 5.2 净流量位置

净流量位置继续由后端事实计算：

```text
净流量位置
= 期末在手库存
+ 开放供应
- 合格需求
```

开放供应与合格需求必须分别生成，不得再通过接近 1 的公共比例使二者机械抵消。净流量位置应比在手库存提前反映已下达供应和需求尖峰，两条曲线在时间上具有可解释的领先/滞后关系。

### 5.3 删除目标净流量位置

从历史缓冲图、图例、表格和页面解释中删除“目标净流量位置”。

不再使用以下内部自定义公式作为展示指标：

```text
（黄区上沿 + 绿区上沿）÷ 2
```

如果为内部 API 向后兼容需要暂时保留可选字段，该字段必须为 `null` 且不得进入计算或显示。

## 6. 参数快照、原因与证据

### 6.1 参数快照

参数快照应能够展开查看：

- 快照编号、状态和生效周段
- 控制点、SKU 和缓冲档案
- ADU、DLT、提前期因子和变异因子
- MOQ、订货周期、DAF 和区域调整因子
- ADU/DLT 来源及截止时间
- 红区基础、安全量、黄区、绿区候选项和最终驱动因素
- 红黄绿区边界及完整计算式

缓冲表现表可以继续显示快照编号，完整内容在选中周/快照的详情区显示。

### 6.2 原因

分开表达两个概念：

- `当周事件`：需求峰值、进口延迟、供应恢复、库存调整或无事件。
- `参数变更原因`：为何从一个参数快照切换到另一个快照。

不得继续使用同一个“原因”字段混合两类含义。

### 6.3 证据

证据状态至少展开为：

- 来源与截止时间存在
- 数量字段完整
- 在手库存连续结转成立
- 净流量恒等式成立
- 当周唯一参数快照匹配
- 红黄绿定容可由参数复算
- 实际需求和尖峰阈值存在

页面保留“完整/证据缺失”的汇总状态，同时显示失败项，不将缺失证据按零处理。

## 7. SKU 级需求波动

- 每个 SKU 使用独立的 52 周需求事实序列。
- 各 SKU 具有不同的基础节奏、尖峰周、波动幅度和恢复过程。
- 尖峰阈值仍由后端根据该 SKU 参数及实际规则计算，不由前端复制公式。
- 图形标题改为：`实际需求波动与尖峰阈值 · {控制点} · {SKU 物料名称} · {窗口}`。
- 同一控制点下切换 SKU 时使用可比较的纵轴上界，避免独立自动缩放掩盖量级差异。

## 8. FPGA 统一主数据

业务已确认：`AV-FPGA-203` 的 MOQ 统一改为 5。

该值作为统一主数据应用于：

- 历史 V1 参数快照
- 历史 V2 参数快照
- 当前状态基线
- 未来场景模拟

所有历史和场景缓冲区必须继续由后端计算器依据统一参数重新计算，不允许前端硬编码红黄绿区域。

预计在现有其他参数不变时：

- V1 红/黄/绿约为 `3/4/6`
- V2 红/黄/绿约为 `2/4/6`

最终值以计算器输出为准，测试不得只断言上述近似展示值。

## 9. 上游产能保护定义

产能保护只对具有有效“上游资源 → 后续 CCR”路由证据的上游资源计算。CCR 自身只显示利用率参照，不计算保护带消耗。

设：

- `P`：上游资源计划可用能力
- `L`：上游资源承诺负荷

当前管理规则为：

```text
保护起点 = 80% × P
保护带宽 = 20% × P
已消耗保护 = clamp(L - 80%P, 0, 20%P)
未用保护余量 = clamp(P - L, 0, 20%P)
超载 = max(0, L - P)
```

80% 是当前管理规则的红区起点，不作为不可配置的行业常数描述。

### 9.1 期间指标

```text
期间平均保护带宽
= 各周保护带宽之和 ÷ 有效周数

期间平均未用保护余量
= 各周未用保护余量之和 ÷ 有效周数

上游保护带余额率
= 各有效上游保护层的期间平均未用保护余量之和
  ÷ 各有效上游保护层的期间平均保护带宽之和
  × 100%
```

该指标不表示 CCR 剩余产能、上游总体利用率或服务水平。

### 9.2 页面位置与命名

- 从“经营结果”移除“剩余保护”。
- 在“能力约束”显示“上游保护带余额率”。
- 同时显示“最低余额率”“保护耗尽周数”“超载周数”。
- 明细术语使用“期间平均保护带宽”和“期间平均未用保护余量”。

## 10. 期间能力图

删除独立的“期间上游负荷分布”图形。

“期间能力”改为所选上游资源的双联产能缓冲图：

### 10.1 左侧：期间利用率观测

- 纵轴使用计划可用能力利用率百分比。
- 每个有效周显示一个利用率观测柱。
- 背景使用固定四色区带：
  - 绿：0–60%
  - 黄：>60–80%
  - 红：>80–100%
  - 深红：>100%
- 纵轴上界至少为 120%，若实际峰值更高则按 10% 向上取整。
- 明确标识期间平均值、峰值和超载观测。

### 10.2 右侧：经验分布

- 使用左侧同一批真实历史利用率观测形成经验频率/密度曲线。
- 不强行拟合正态分布，不把平滑曲线解释为统计预测。
- 低利用率侧标识“可用于吸收波动或扩大产量的余量”。
- 红区和深红区标识“可能成为流程干扰点的风险”。
- 继续沿用四色规则，不增加蓝区。

理论能力、标准能力、经验证能力和计划可用能力保留在下方证据明细，不再作为多条横线叠加到主图。

## 11. 当前基线与历史经营结果

页面必须说明两类指标的口径差异：

- 历史经营结果：过去 26/52 周的期间平均、累计或极值。
- 当前状态基线：会前截止时点的库存、WIP、积压、供应承诺和能力快照；服务水平等指标可使用明确标注的滚动窗口。

当前基线详情增加内部历史衔接信息：

- 来源事实集
- 最近历史截止
- 基线截止
- 对账范围
- 增加、减少、调整和差异
- 对账结论

冻结完整性检查必须把关键存量指标的衔接对账纳入证据；对账缺失或不平时，不允许把候选基线标记为证据完整。

## 12. 测试与验收

### 12.1 单元和领域测试

- 验证 80% 保护起点、20% 保护带宽、保护消耗、余额和超载公式。
- 验证保护指标只适用于具有有效后续 CCR 证据的上游资源。
- 验证期间平均、最低余额、耗尽周和超载周统计。
- 验证每个 SKU 的在手库存连续结转恒等式。
- 验证净流量恒等式并确认开放供应不再机械抵消合格需求。
- 验证不同 SKU 的需求序列不是固定比例缩放。
- 验证 FPGA MOQ 在历史、当前基线和未来场景中均为 5。
- 验证历史期末至当前基线的余额桥接和证据拦截。

### 12.2 API 和 UI 测试

- 历史缓冲结果不再输出或显示有效的“目标净流量位置”。
- 图形标题明确显示当前控制点和 SKU，切换后数据与标题同步变化。
- 参数快照、当周事件、参数变更原因和证据清单含义分离。
- “经营结果”不再显示“剩余保护”。
- “能力约束”显示新的保护术语、最差周和异常周数。
- “期间上游负荷分布”容器不存在。
- 新“期间能力”包含期间观测和经验分布两个部分，四色阈值正确。
- 当前基线显示历史衔接与对账信息。
- 6 个月和 12 个月窗口继续产生不同的汇总和分布结果。

### 12.3 回归和边界检查

- 运行全部现有及新增测试。
- 运行 `dotnet build AdaptiveSopDdsop.sln --no-restore -m:1`，要求零警告零错误。
- 回归“白盒追踪”和“公开演示闭环”的入口、按钮和运行行为。
- 最终检查 Git 差异，确认 CONTRACT、SDBR 契约实现、fixtures、协议测试和 Network 仓库没有变化。

## 13. 非目标

- 不以本次内部演示事实链替代未来正式 ERP/MES/WMS 数据适配器。
- 不建立完整生产排程、采购下达或库存执行模块。
- 不把经验分布用于自动决策、自动参数采纳或自动批准。
- 不修改任何外部系统契约。
